# 投递助手（Chrome 扩展）
以前投实习的时候，我还是坚持手搓 Excel，一条一条复制公司、岗位、链接和 JD。
但秋招要投的岗位一多，光整理信息就很费时间。于是我做了一个 Chrome 插件：打开岗位详情页，点一下插件，就能自动抓取当前岗位的信息。

它可以记录：
岗位名称、公司、地点和岗位链接、完整 JD 原文、投递日期和使用的简历版本、投递进度（已投递/笔试/面试等）。

确认后，岗位会直接进入投递看板。之后可以搜索公司、岗位和 JD 关键词，修改投递日期和进度，随时回看原岗位链接，还能把全部记录导出成 Excel。
同一个岗位链接重复保存也不会堆出一排重复记录，而是保留最新一次更新。
部分招聘网站对公司、部门的标注比较混乱，所以插件还支持配置自己的 DeepSeek API Key，打开插件后让 AI 自动结合网页文字与截图识别岗位信息，并直接填入表单；不想使用 AI 的话，也可以直接在保存前手动修改。

界面采用星露谷田园像素风设计。

## 安装

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择下载或克隆后的项目文件夹。
5. 把“投递助手”固定到浏览器工具栏。

## 使用

1. 打开岗位详情网页，确认页面上已经显示完整 JD。
2. 点击工具栏中的“投递助手”。
3. 核对自动提取结果，选择简历版本，点击“保存为已投递”。
4. 保存后点击下方“查看投递看板”，即可搜索 JD、查看原链接，或修改投递日期与进度。

进度支持“简历挂”，可在记录、编辑和筛选中选择；此状态不计入“进行中”。

## 多模态 AI 识别（0.5.3）

打开岗位详情页，将岗位标题、地点等关键信息滚动到可见区域，再打开插件。配置好 AI 后，每次打开插件都会自动开始识别，无须另点按钮；首次保存 AI 设置后也会立即识别。关闭 AI 时仍使用本地提取。插件会读取最新页面文字、截取当前可见区域，一起识别公司、岗位、地点、部门、业务方向／团队，并为五项显示判断依据。

长页面、图片 JD 或屏幕外的组织介绍可通过“补充招聘页截图”选择多张 PNG、JPEG 或 WebP。当前截图和补充图片只用于本次请求，不写入投递记录。截图失败时会明确报错，不会悄悄降级成纯文字识别。

首次使用在“AI 设置”填写对应 API Key。已有 Key 保留，无须重新填写。

- DeepSeek 使用支持图片的 `deepseek-flash` 与 Chat Completions 接口，参见[官方视觉文档](https://api-docs.deepseek.com/guides/vision/)。
- OpenAI 使用 Responses API 的图片输入与结构化输出。
- 每次打开插件会自动发送网页文字和当前可见区域截图给所选服务商；补充截图后点击“重新识别”可再次请求。识别失败时显示原因，由用户点击重试。
- AI 有内容和依据的识别结果会直接填入表单，包括替换已有规则提取结果；不再按置信度要求逐项确认。手动编辑（包括清空）的字段不会自动覆盖。
- 不再显示逐项结果卡片和“采用”按钮；识别依据保留在表单字段下方，发现错误可直接修改。
- 部门、公司、岗位和地点必须有明确页面证据；业务方向允许标记为“语义推断”。
- API Key 分开保存在当前 Chrome 配置的扩展本地存储中，不会进入投递记录或 Excel。

更新已有扩展：在 `chrome://extensions/` 找到“投递助手”，点击重新加载，然后重新打开岗位页上的插件。若原先加载的是其他位置的副本，需要将该副本更新为本目录内容；不要卸载原扩展，以免丢失记录。

看板右上角可以导出 Excel `.xlsx` 表格，包含公司、岗位、部门、业务方向、字段识别依据、地点、投递时间、简历版本、进度、岗位链接、JD 原文和备注。投递数据保存在这个 Chrome 配置的扩展本地数据库中；卸载扩展前请先导出表格。

## 当前边界

- 能读取普通岗位详情页和提供 Schema.org `JobPosting` 数据的页面。
- 浏览器内部页面、PDF、Chrome 应用商店页面不能读取。
- 图片、画布或跨域 iframe 中可见的岗位信息可交给视觉识别；未显示或截图未覆盖的内容仍需补充。AI 本轮只提取五项字段，不负责转录完整 JD，图片 JD 的原文仍需人工补充。
- 不会自动读取邮箱，也不会自动判断你是否真的点击了招聘网站的“提交申请”。只有你点击扩展并确认保存后，记录才成立。
- AI 补全依赖所选服务商的 API 账户与可用额度；没有配置 API Key 时，其余本地采集、保存、看板和 Excel 功能仍可正常使用。
